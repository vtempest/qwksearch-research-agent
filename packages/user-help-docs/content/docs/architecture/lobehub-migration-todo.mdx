# LobeHub Migration To-Do

The working checklist behind the
[LobeHub Packages Migration Plan](./lobe-packages-migration-plan). The plan says
*what* the target architecture is; this page tracks *where each piece stands* and
what the next concrete step is. Every item names the file that owns it, so a run
can pick one up without re-deriving the seam.

The map of what already connects is
[LobeHub Integrations Reference](./lobehub-integrations).

## Phase 1 — Chat mode powered by the engine

### 1.1 Stand up staging ⬜

Needs Cloudflare account access, so it cannot be done from a code-only run.

1. `cd packages-lobe && pnpm install && bun run build:worker`
2. Create the Hyperdrive config and paste the id into `wrangler.jsonc`
   (or set `DATABASE_URL` to a Neon URL and keep `DATABASE_DRIVER=neon`).
3. `bun run db:migrate` (Postgres, 157 migrations) and `bun run cf:d1:migrate` (D1).
4. `bun run cf:deploy`, then smoke `/api/health`,
   `/trpc/lambda/config.getGlobalConfig`, `/signin`.

Until then, `bun run cf:dev` (local wrangler, dummy secrets, local D1/KV) is the
only end-to-end check available.

### 1.2 Search tool = `search-web-api` ✅

Done: `apps/server/src/services/search/impls/qwksearch/` implements
`SearchServiceImpl` against Worker A's `GET /api/agent/search`; registered as
`SearchImplType.QwkSearch`; enabled via `SEARCH_PROVIDERS=qwksearch` in
`wrangler.jsonc`. Category normalization, 3-way fan-out, URL-merge and failure
mapping are covered by `impls/qwksearch/index.test.ts` (20 cases). The contract
is written up in §F5 of the integrations reference.

Follow-ups that are deliberately *not* in that change:

- ✅ **Extend the tool manifest's category enum.** Done the second way the
  option offered: `packages/builtin-tool-web-browsing/src/searchCategories.ts`
  (new file) resolves the enum at module evaluation and widens it *only* when
  `SEARCH_PROVIDERS` names `qwksearch` and nothing else, so no other backend is
  ever asked for a category it cannot serve. `manifest.ts` gains an import and
  swaps the literal for `resolveSearchCategories()`; the package index gains one
  export line. Those three lines are the whole upstream edit.

  The widening is to **ten**, not thirteen — the fan-out endpoint takes SearXNG
  spellings, and QwkSearch's 13-name registry aliases onto those ten in
  `normalizeCategories`. The five the model gains are `files`, `it`, `map`,
  `music` and `social+media`. Drift between the advertised list and the accepted
  one now fails a test in `impls/qwksearch/index.test.ts` (27 cases, was 20).

  Two caveats worth knowing: the enum is fixed at module evaluation, which is
  safe on the Worker only because `worker/cf/globals.ts` mirrors vars onto
  `process.env` before anything else evaluates; and in the SPA there is no
  `process`, so the client-side copy of the manifest always reports LobeHub's
  five. Nothing on the client reads the enum today.
- ⬜ **Service binding instead of HTTPS.** `QwkSearchImpl` calls Worker A over
  the public internet. Once both Workers deploy together, a Cloudflare service
  binding removes a hop and the need for `QWKSEARCH_API_KEY`.
- ⬜ **Ranking parity.** The fan-out's scores come from `search-web-api`;
  `domain-rank` (favicons, domain authority) is not consulted on the engine side.
  Decide whether that belongs in the endpoint or the impl.

### 1.3 Extraction chain over the QwkSearch extractors ✅

Done: `worker/qwksearch/extract.ts` now picks its chain per URL kind
(`defaultTiersFor`) and builds articles with QwkSearch's extractors. The contract
is written up in §F2 of the integrations reference; 35 cases cover it in
`worker/qwksearch/extract.test.ts`.

1. ✅ `extract-webpage`'s `extractContentAndCite` is the primary HTML → article
   path in `articleFromHtml`, with LobeHub's readability pass
   (`articleFromHtmlViaCrawler`) as the fallback. This is what restores
   `author_cite` / `author_short` / `author_type` / chrono-parsed dates and keeps
   images, links and headings in the HTML written to D1 `articleCache`.

   **Deviation from the original plan, deliberately:** it is not "tier 0 ahead of
   the scraper". `extractContent`'s own fetch stack would duplicate the Puppeteer
   scraper and put an unrendered fetch in front of it, which is exactly the tier
   the chain already ends with. Making it the *converter* every HTML-bearing tier
   uses upgrades the scraper tier too, rather than racing it.
2. ✅ YouTube URLs are their own `UrlKind` (`youTubeVideoId` covers watch,
   `youtu.be`, `embed`, `shorts`, `live`) and lead with `extract-youtube`
   transcripts, regrouped into ~90-word paragraphs, titled from YouTube's oEmbed
   endpoint. The web chain stays underneath for captions-disabled videos.
3. ✅ PDF and arXiv URLs lead with `extract-pdf` and fall back to Tavily;
   `pdfUrlFor` rewrites arXiv `/abs/` to `/pdf/`. `PDF_PROCESSOR_URL` opts into
   `hybrid` processing so pages with no text layer get Granite Docling OCR.
4. ✅ Every tier still returns `{ error }` rather than throwing, including on a
   failed dynamic `import()` of one of the three packages.

Follow-ups that are deliberately *not* in that change:

- ⬜ **Measure the Worker bundle.** `extract-webpage` is ~1 MB unminified
  (linkedom, chrono-node, a 92k-name corpus). All three packages are `import()`-ed
  so they stay off the cold-start path, but code-splitting does not reduce the
  *total*, and the budget is ~7.4 MB gzipped against Cloudflare's 10 MB limit.
  Run `bun run build:worker` and record the new number in
  `packages-lobe/README.md` before the next deploy.
- ⬜ **DOCX and Google Docs.** `extract-webpage`'s `extractContent` also handles
  `.docx` buffers and rewrites Google Docs URLs to their export endpoints. Neither
  is wired into `defaultTiersFor` yet.
- ⬜ **Cache the extractor's `via`.** D1 `articleCache` has no column recording
  which tier produced a row, so a cached article cannot be re-extracted
  selectively when a tier improves.
- ⬜ **`extract-youtube` ships no types.** The published `1.0.256` tarball has
  `dist/index.mjs` and `dist/index.cjs` but neither the `.d.ts` its
  `exports.types` points at nor `dist/react/`, so consumers resolve it as `any`.
  `packages-lobe/src/types/shim-extract-youtube.d.ts` declares the used surface
  as a stopgap; delete it once a release ships declarations. The cause is not in
  the repo — `npm pack` includes `dist/*.d.ts` from a local build either way, and
  `.github/workflows/npm-publish.yml` refuses to publish a package whose `build`
  fails — so it needs the publish logs, not another read of the manifest.
  `packages/extract-youtube/package.json` gained the `files` field its two
  sibling packages already have, which is tarball hygiene, **not** a fix for
  this.

### 1.4 Agent parity checklist ⬜

Reproduce today's chat-mode behavior on the engine and record each gap:

- ⬜ Search-cited answers with follow-up suggestions (LobeHub has both — verify
  they read the QwkSearch results from 1.2).
- ⬜ File-upload Q&A.
- ⬜ Voice input — LobeHub's TTS/STT settings tab vs `use-voice-control`; decide
  per gap whether to adopt or port.
- ⬜ Guest / anonymous chat with rate limiting. Worker A has
  `lib/rate-limit/guestRateLimiter.ts`; the engine requires sign-in. Decide
  *before* cutover: anonymous session mode, or chat becomes login-gated.

## Phase 2 — Settings: one system of record

- ⬜ **2.1 Map every section** of `research-agent-ui/src/settings/sections.json`
  to its engine equivalent: models → `Settings/provider` + `service-model`;
  mcpservers → `features/MCP/MCPSettings`; voice → `tts`; skills-memory →
  `skill` + `memory`; account/storage → `profile` / `storage`.
- ⬜ **2.2 Add the two missing panes**, following the existing tab conventions
  (`src/features/Settings/<tab>/` + route segment + keys in
  `packages/locales/src/default/qwksearch.ts`): **Search & Sources** (engine and
  category selection, per-category defaults, time range, SearXNG URL — now that
  1.2 exists these map onto `QWKSEARCH_SEARCH_URL` and the category normalizer)
  and **Extraction** (citation style, transcript language, render backend,
  scraper/Tavily keys). After 1.3 the extraction pane has real knobs to bind to:
  `YouTubeConfig.languages`, `PdfConfig.processorUrl` (`PDF_PROCESSOR_URL`) and
  the scraper deadline. Persist through `src/store/user/slices/settings/`.
- ⬜ **2.3 Key migration.** Server env keys stay Worker secrets. Per-user keys
  live in `localStorage` today and have no server copy — announce a one-time
  re-entry into the engine's key vault; do not build a migrator.
- ⬜ **2.4 Retire the old surface** only after the map is covered: delete
  `apps/qwksearch-web/components/Settings/**`, `app/settings/[[...section]]`,
  `app/api/config`, and drop `shadcn-settings` from the prebuild chain. Never run
  two settings stores at once.

## Phase 4 — Public cutover 🔒

Blocked on the LobeHub Community License answer, recorded in
`packages-lobe/README.md` before any public traffic moves.

- 🔒 **4.1 Routing split.** `/chat*`, `/settings*`, `/docs*`, `/signin*`,
  `/_spa*`, `/webapi/*`, `/trpc/*`, `/api/auth/*`, `/f/*` → engine; everything
  else (homepage, marketing, `/api/doc/*`, `/api/agent/search`) → Worker A.
- 🔒 **4.2 One login.** Both sides run Better Auth 1.6. Consolidate on the
  engine's instance; Worker A reads the session via `/api/auth/get-session` on
  the same cookie domain. Migrate `user`/`account` rows D1 → Postgres.
- 🔒 **4.3 Chat history migration.** One-shot D1 `chats`/`messages` → Postgres
  topics/messages/sessions, dry-run on a snapshot, D1 read-only for 30 days.
- 🔒 **4.4 Homepage handoff.** The hero search box submits into `/chat?q=…`;
  `app/page.tsx` stops mounting `ChatWindow`/`ChatInputBox`.
- 🔒 **4.5 Decommission in Worker A**: `app/api/agent/**` (except `search`),
  `lib/chat/**`, `app/c/[chatId]`, the `ChatProvider` mount, the NDJSON protocol.
  `/c/:id` 301s to migrated topics.

## Phase 5 — Replace the rest

- ⬜ **5.1 Package fates.** Keep + publish: `search-web-api`, `extract-*`,
  `render-url-to-html`, `domain-rank`, `reason-editor(-sidebar)`,
  `qwksearch-mcp-server`, `qwksearch-api-client` (regenerate against `/api/v1`).
  Freeze: `research-agent-ui`, `use-voice-control`. Deprecate:
  `chat-agent-toolkit`'s live chat path, `write-language`, `shadcn-settings`.
- ⬜ **5.2 Satellite apps.** Browser and VS Code extensions re-point to the
  engine (`/webapi`, `/api/v1`); desktop picks Lobe's Electron app or keeps Tauri
  as a webview.
- ⬜ **5.3 Trim the prebuild chain** in `apps/qwksearch-web/package.json`.
- ⬜ **5.4 Ops gaps**, all from `packages-lobe/README.md` § Known gaps:
  - ⬜ Upstash HTTP Redis provider in `src/libs/redis` — without it, agent stream
    fan-out, edit locks and some rate limits run on per-isolate memory.
  - ⬜ Mobile SPA build (`build:spa:mobile`); mobile currently gets the desktop bundle.
  - ⬜ Worker bundle size budget in CI (~7.4 MB gzipped against a 10 MB limit).
  - ⬜ OIDC (`/oidc/*` returns 501) — blocks CLI and desktop sign-in.
  - ⬜ SEO strings in the HTML shell are English-only (`worker/shims/serverTranslation.ts`).
  - ⬜ No `sharp`; avatar processing falls back to the original image.

## How to pick up the next item

1. Prefer an item whose seam is already understood and whose "done" is testable
   without Cloudflare credentials — those are the ones a code-only run can finish.
2. Keep changes **additive**: new files under `worker/`, `src/features/QwkSearch/`
   or a new `impls/` directory. Edits to upstream files are the merge cost against
   LobeHub, so keep them to registration points (an enum, a switch, a route mount)
   and list every one in `packages-lobe/README.md` § What changed vs. upstream.
3. Ship a test with it. `bunx vitest run <path>` under `packages-lobe`.
4. Update this page's status and add the seam to the integrations reference in
   the same change.
