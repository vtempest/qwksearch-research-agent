# LobeHub Integrations Reference

The complete inventory of **where QwkSearch and LobeHub touch each other**. The
strategy doc is [LobeHub Packages Migration Plan](./lobe-packages-migration-plan)
(what we're building toward) and the running work list is
[LobeHub Migration To-Do](./lobehub-migration-todo). This page is the *map*:
what exists today, in which file, and what it depends on.

Scope: `packages-lobe/` — the adapted LobeHub v2.2.13 monorepo that runs as one
Cloudflare Worker. Keep it current whenever an integration is added, moved or
removed; it is the merge contract against upstream LobeHub, so every entry
should name real files.

## Direction of the integration

The dependency runs **one way**: QwkSearch code is added *into* the LobeHub tree.
No package under `packages/` or `apps/` depends on `@lobehub/*` or `@lobechat/*`
— verified by the absence of those names in every workspace `package.json`. That
matters for the license gate: the QwkSearch workspace is not a LobeHub derivative
work; `packages-lobe/` is.

The two workspaces stay separate (bun/turbo vs pnpm). The only bridges are
**published npm packages** and **shared Cloudflare bindings** — never workspace
links. See §1 of the migration plan for why merging them is not on the table.

The npm bridges in place today, all declared in `packages-lobe/package.json` and
resolved from the registry rather than `../packages/`:

| Package | Source of truth | Used by |
|---|---|---|
| `extract-webpage` | `packages/extract-webpage` | F2 — `extractContentAndCite` over rendered HTML |
| `extract-youtube` | `packages/extract-youtube` | F2 — the YouTube transcript tier |
| `extract-pdf` | `packages/extract-pdf` | F2 — the PDF/arXiv tier |

Publishing is the update path: a fix in `packages/extract-*` reaches the engine
through `npm publish` (the `ship` script in each package) and a version bump in
`packages-lobe/package.json`, not through a workspace link.

## 1. Runtime integrations — LobeHub on Cloudflare Workers

These make upstream LobeHub run on workerd at all. They are ports, not features.

| # | Integration | Files | Replaces |
|---|---|---|---|
| R1 | Hono Worker entry + route composition | `worker/index.ts`, `worker/app.ts` | Next.js route handlers + middleware |
| R2 | Bindings bridge (env, per-request context, eager `process.env` mirror) | `worker/cf/{env,globals,requestContext}.ts` | Node `process.env` |
| R3 | Route shells: auth, tRPC, `/webapi/*`, `/api/v1`, SPA | `worker/routes/{auth,trpc,webapi,api,spa}.ts` | `src/app/(backend)` shells |
| R4 | Node/Next shims (21 modules: `next/*`, `ioredis`, `nodemailer`, `sharp`, `oidc-provider`, `pglite`, `ws`, `undici`, …) | `worker/shims/` | packages unavailable on workerd |
| R5 | Postgres over Hyperdrive | `packages/database/src/core/web-server.ts` (`resolveHyperdriveConnectionString`), `HYPERDRIVE` binding | `pg` pool / Neon URL |
| R6 | Better Auth secondary storage on KV | `src/libs/better-auth/utils/config.ts` (`createKVSecondaryStorage`) | Redis |
| R7 | Email through Cloudflare Email Routing | `apps/server/src/services/email/impls/cloudflare/`, `packages/env/src/email.ts` | nodemailer / Resend |
| R8 | SPA asset serving + per-request `window.__SERVER_CONFIG__` injection | `worker/routes/spa.ts`, `worker/routes/spaVariants.ts`, `scripts/buildWorkerAssets.mts`, `ASSETS` binding | Next.js static serving |
| R9 | Worker bundle build + deploy | `vite.worker.config.ts`, `wrangler.jsonc`, `wrangler.local.jsonc`, `wrangler.smoke.jsonc`, `build:worker*` / `cf:*` scripts | `next build` |

**Mount order in `worker/app.ts` is load-bearing**: Better Auth first (`/api/auth/*`
must not be shadowed), then the QwkSearch feature routes (their `/api/doc/*` and
`/api/agent/article-*` paths are more specific than LobeHub's `/api/agent` app),
then LobeHub's tRPC/webapi/api, then the SPA catch-all.

### F1 — Article panel contract

- Opens on any external link click inside a chat message; modifier and middle
  clicks keep the browser default.
- Programmatic open:
  `window.dispatchEvent(new CustomEvent('qwksearch:open-article', { detail: { url } }))`.
- `GET /api/doc/article?url=…` returns a cached article (hit count tracked) or
  runs F2 fresh. `POST /api/doc/article` stores a Q&A pair or updates follow-ups.
- Q&A and follow-ups run through LobeHub's `AiGenerationService`, so the signed-in
  user's own providers and key vaults apply — no separate key path.

### F2 — Extraction chain contract

The seam that makes the engine's article panel extract the way QwkSearch does. Three
QwkSearch packages are consumed from npm; none is a workspace link.

`defaultTiersFor(url)` picks the chain from `classifyUrl`:

| URL kind | Tiers, in order | Notes |
|---|---|---|
| `article` | Puppeteer scraper (`SCRAPER_URL`, 8s deadline) → Tavily (`TAVILY_API_KEY`) → `@lobechat/web-crawler` | unchanged ordering |
| `youtube` | `extract-youtube` transcript → the three web tiers | the web chain stays underneath so a captions-disabled video still yields the watch page |
| `pdf` | `extract-pdf` → Tavily | scraper and crawler cannot read PDF bytes, so they are not in this chain |
| `search-engine`, `invalid` | none — rejected 400 by the route | |
| `video` (vimeo, dailymotion, twitch) | none — the route returns its "video content" stub | |

Two classifier additions carry this: `youTubeVideoId` (watch, `youtu.be`, `embed`, `shorts`,
`live`) and `pdfUrlFor` (any `.pdf` path, plus arXiv `/abs/` rewritten to `/pdf/` so the paper is
extracted rather than the landing page).

**Rendered HTML → article** runs through `articleFromHtml`, which calls `extract-webpage`'s
`extractContentAndCite` first and falls back to `articleFromHtmlViaCrawler` (LobeHub's readability
pass) on an empty result or a throw. That first path is the whole point of the integration: it is
the only one producing `author_cite`, `author_short`, `author_type` and chrono-parsed `date`, and
its HTML keeps images, links and headings instead of round-tripping through markdown. Those columns
already exist in D1 `articleCache`, so the richer metadata lands with no schema change.

| Concern | Behavior |
|---|---|
| Loading | All three packages are `import()`-ed inside their tier. `extract-webpage` alone is ~1 MB (linkedom, chrono-node, a 92k-name corpus), so it must stay off the cold-start path |
| Degradation | A failed dynamic import returns `null` and the tier reports `{ error }` — extraction never throws because a package is missing |
| Contract | Every tier still returns `{ error }` rather than throwing; `extractArticle` advances on any result without usable `html` |
| YouTube metadata | Title and channel come from `https://www.youtube.com/oembed`, best-effort with a 5s timeout; the fallback title is `YouTube video <id>` |
| Transcripts | Captions are regrouped into ~90-word paragraphs — YouTube returns them as one unbroken run |
| PDF OCR | `PDF_PROCESSOR_URL` (optional) switches `extract-pdf` to `hybrid`, sending only pages with no usable text layer to a Granite Docling processor |
| Injection seams | `articleFromHtml({ extractCite })`, `extractViaYouTube({ transcript, fetcher, languages })`, `extractViaPdf({ convert, processorUrl })` — every tier is unit-testable without network |

### F5 — Search provider contract

The seam that makes LobeHub's agent search *QwkSearch's* index.

```
LobeHub web-browsing tool
  → SearchService (apps/server/src/services/search/index.ts)
    → SearchImplType.QwkSearch → QwkSearchImpl
      → GET {QWKSEARCH_SEARCH_URL}?q=…&cat=…&recency=…
        → Worker A: apps/qwksearch-web/app/api/agent/search
          → research-agent-ui createSearchHandler
            → search-web-api searchWeb() → search.qwksearch.com (SearXNG) → 100+ engines
```

| Concern | Behavior |
|---|---|
| Enable | `SEARCH_PROVIDERS=qwksearch` (set in `wrangler.jsonc` vars) |
| Endpoint | `QWKSEARCH_SEARCH_URL`, default `https://qwksearch.com/api/agent/search`; optional `QWKSEARCH_API_KEY` sent as a bearer token |
| Categories | Three vocabularies are normalized onto the endpoint's ten SearXNG names: LobeHub's manifest, QwkSearch's 13-category registry (`academic`, `social`, `tech`, `torrents`, …) and SearXNG's. Unknown names fall back to `general` rather than returning an empty page |
| Advertised categories | The manifest enum is resolved at module evaluation by `packages/builtin-tool-web-browsing/src/searchCategories.ts`. With `SEARCH_PROVIDERS=qwksearch` and nothing else, the model is offered all ten (`files`, `it`, `map`, `music`, `social+media` on top of LobeHub's five); any other configuration keeps LobeHub's five, so no backend is asked for a category it cannot serve |
| Fan-out | One request per category, capped at 3, issued in parallel |
| Merge | Deduplicated by URL — highest score wins, engine lists union, a missing snippet is backfilled from the duplicate |
| Engines | Never forwarded. `useAutoSearchEngineSelection = true` tells `SearchService` not to retry by stripping engine restrictions, because QwkSearch already picks engines per category |
| Failure | Any category request failing raises `TRPCError SERVICE_UNAVAILABLE`, so `SearchService` can fail over to the next configured provider |

Four upstream lines are edited for this, all registration points: the
`SearchImplType` enum, the factory switch in
`apps/server/src/services/search/impls/index.ts`, and in
`packages/builtin-tool-web-browsing/` the manifest's import + enum expression
and one export line in `src/index.ts`. Everything else is new files —
`impls/qwksearch/` and `builtin-tool-web-browsing/src/searchCategories.ts`.

Note that `packages/**` is excluded from the root Vitest config and the
web-browsing tool package has no config of its own, so a test placed beside
`searchCategories.ts` would never run. Its coverage lives in
`impls/qwksearch/index.test.ts` instead, which imports the package by name.

## 3. Shared infrastructure

Both Workers point at the **same** Cloudflare resources, which is what makes a
gradual cutover possible at all.

| Binding | Resource | Shared with `apps/qwksearch-web`? |
|---|---|---|
| `DB` | D1 `qwksearch-new` (`b0ba9a66-…`) | ✅ same database id |
| `KV` | KV `c53d894414bb…` | ✅ same namespace id |
| `R2` | `qwksearch-uploads` | ✅ |
| `EMAIL` | Email Routing → `noreply@qwksearch.com` | ✅ |
| `HYPERDRIVE` | Postgres for LobeHub's 169-table schema | ❌ engine-only |
| `ASSETS` | SPA bundles | ❌ engine-only |

D1 tables the engine reads and writes: `articleCache`, `articleQA`, `favorites`,
`documents`, `research_quotes`, `share_tokens`, `google_docs_sync` — created
idempotently by `migrations/d1/0001_qwksearch_tables.sql` (`bun run cf:d1:migrate`).

LobeHub's own data stays on Postgres (169 tables, 211 `jsonb` columns, 11
`pgvector` columns, ~380 raw SQL fragments, 157 migrations). Porting it to D1
would be a rewrite of the data layer, not a runtime port.

## 4. Configuration surface

Vars in `wrangler.jsonc` (both the default and `production` env):
`APP_URL`, `DATABASE_DRIVER`, `DISABLE_REDIS`, `EMAIL_SERVICE_PROVIDER`,
`SMTP_FROM`, `SCRAPER_URL`, `SEARCH_PROVIDERS`, `QWKSEARCH_SEARCH_URL`.

Optional, unset by default: `PDF_PROCESSOR_URL` (F2's Granite Docling OCR
processor for scanned PDFs).

Secrets (`wrangler secret put`): `KEY_VAULTS_SECRET`, `AUTH_SECRET`,
`DATABASE_URL` (when not using Hyperdrive), `S3_*`, `TAVILY_API_KEY`,
`SCRAPER_API_KEY`, `QWKSEARCH_API_KEY`, per-provider model keys, `QSTASH_*`.

## 5. Style seam

**antd 6 + `@lobehub/ui` + antd-style inside the engine; Tailwind 4 + shadcn
outside** (homepage, marketing, REASON editor). No cross-imports between
`packages-lobe/src` and `packages/research-agent-ui`. The one planned exception
is the REASON editor mounted inside the engine's `/docs` page — it ships its own
scoped stylesheet (`react-reason-editor/style.css`).
