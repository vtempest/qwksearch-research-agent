# LobeHub Migration To-Do

The working checklist behind the
[LobeHub Packages Migration Plan](./lobe-packages-migration-plan). The plan says
*what* the target architecture is; this page tracks *where each piece stands* and
what the next concrete step is. Every item names the file that owns it, so a run
can pick one up without re-deriving the seam.

The map of what already connects is
[LobeHub Integrations Reference](./lobehub-integrations).

## Phase 1 — Chat mode powered by the engine

### 1.1 Stand up staging ⬜

Needs Cloudflare account access, so it cannot be done from a code-only run.

1. `cd packages-lobe && pnpm install && bun run build:worker`
2. Create the Hyperdrive config and paste the id into `wrangler.jsonc`
   (or set `DATABASE_URL` to a Neon URL and keep `DATABASE_DRIVER=neon`).
3. `bun run db:migrate` (Postgres, 157 migrations) and `bun run cf:d1:migrate` (D1).
4. `bun run cf:deploy`, then smoke `/api/health`,
   `/trpc/lambda/config.getGlobalConfig`, `/signin`.

Until then, `bun run cf:dev` (local wrangler, dummy secrets, local D1/KV) is the
only end-to-end check available.

### 1.2 Search tool = `search-web-api` ✅

Done: `apps/server/src/services/search/impls/qwksearch/` implements
`SearchServiceImpl` against Worker A's `GET /api/agent/search`; registered as
`SearchImplType.QwkSearch`; enabled via `SEARCH_PROVIDERS=qwksearch` in
`wrangler.jsonc`. Category normalization, 3-way fan-out, URL-merge and failure
mapping are covered by `impls/qwksearch/index.test.ts` (20 cases). The contract
is written up in §F5 of the integrations reference.

Follow-ups that are deliberately *not* in that change:

- ✅ **Extend the tool manifest's category enum.** Done the second way the
  option offered: `packages/builtin-tool-web-browsing/src/searchCategories.ts`
  (new file) resolves the enum at module evaluation and widens it *only* when
  `SEARCH_PROVIDERS` names `qwksearch` and nothing else, so no other backend is
  ever asked for a category it cannot serve. `manifest.ts` gains an import and
  swaps the literal for `resolveSearchCategories()`; the package index gains one
  export line. Those three lines are the whole upstream edit.

  The widening is to **ten**, not thirteen — the fan-out endpoint takes SearXNG
  spellings, and QwkSearch's 13-name registry aliases onto those ten in
  `normalizeCategories`. The five the model gains are `files`, `it`, `map`,
  `music` and `social+media`. Drift between the advertised list and the accepted
  one now fails a test in `impls/qwksearch/index.test.ts` (27 cases, was 20).

  Two caveats worth knowing: the enum is fixed at module evaluation, which is
  safe on the Worker only because `worker/cf/globals.ts` mirrors vars onto
  `process.env` before anything else evaluates; and in the SPA there is no
  `process`, so the client-side copy of the manifest always reports LobeHub's
  five. Nothing on the client reads the enum today.
- ⬜ **Service binding instead of HTTPS.** `QwkSearchImpl` calls Worker A over
  the public internet. Once both Workers deploy together, a Cloudflare service
  binding removes a hop and the need for `QWKSEARCH_API_KEY`.
- ⬜ **Ranking parity.** The fan-out's scores come from `search-web-api`;
  `domain-rank` (favicons, domain authority) is not consulted on the engine side.
  Decide whether that belongs in the endpoint or the impl.

### 1.3 Extraction chain, tier 0 = the QwkSearch article extractor ✅

Done. `worker/qwksearch/extractQwkSearch.ts` adapts `extract-webpage`, and
`tiersForUrl` in `worker/qwksearch/extract.ts` routes each URL kind to its chain.
One `extractContent` call covered all three sub-items, because the extractor
branches on the URL itself.

1. ✅ **Tier 0 = `extract-webpage`**, ahead of the scraper, bringing citation
   extraction (`author_cite`, `author_short`, `author_type`, date, source) that
   the readability path could not produce. It writes through the same D1
   `articleCache`, so nothing about the panel's storage changed.
2. ✅ **YouTube** is its own `UrlKind`, extracted as a transcript through
   `extract-youtube`, instead of being rejected in `VIDEO_PATTERNS`. Only
   Vimeo/Dailymotion/Twitch — hosts with no transcript route — still get the
   "not an article" stub.
3. ✅ **PDF and arXiv** are their own `UrlKind`, routed to `extract-pdf`
   through the extractor's PDF branch. `.pdf` (with or without a query string)
   and `arxiv.org/pdf/` match; `arxiv.org/abs/` stays on the article path
   because those pages are HTML.
4. ✅ Every tier still returns `{ error }` rather than throwing — including a
   failed *module load*, which is why the package is behind an injectable lazy
   loader. Tests inject a fake module, so they never load the real extractor.

Two things worth knowing before building on this:

- **`linkedom` is no longer shimmed** in `vite.worker.config.ts`. It was stubbed
  to throw because LobeHub only reached it from the dev-server template
  rewriter, but `extract-webpage` parses every page with it and it runs fine on
  workerd. `worker/shims/linkedom.ts` is gone. The Worker bundle went from
  **7.39 MB to 7.93 MB gzipped** against Cloudflare's 10 MB limit — see 5.4.
- **The scraper tier got better too.** When tier 0 fails but Puppeteer gets past
  the bot check, the rendered HTML now runs through the same citation extraction
  (`articleFromRenderedHtml`) instead of discarding the byline. It falls back to
  LobeHub readability if that yields nothing.

Follow-ups that are deliberately *not* in that change:

- ✅ **Per-user extraction settings — resolution layer.** Done in 1.5 below;
  what remains is the UI that writes to it (2.2).
- ✅ **PDF OCR modes.** `PDF_PROCESSOR` /
  `PDF_PROCESSOR_URL` reach `extract-pdf` through 1.5.
- ⬜ **Bundle budget in CI** (5.4) matters more now that the margin is ~2 MB.

#### 🔒 Open question: two chains live in `extract.ts`

`extract.ts` currently defines **two** tier chains, and only one of them runs:

| | `tiersForUrl` (live) | `defaultTiersFor` (not wired) |
|---|---|---|
| article | `qwksearch → scraper → tavily → crawler` | `scraper → tavily → crawler` |
| youtube | `qwksearch` | `extractViaYouTube → scraper → tavily → crawler` |
| pdf | `qwksearch` | `extractViaPdf → tavily` |

`extractArticle` defaults to `tiersForUrl`, so `extractViaYouTube` and
`extractViaPdf` — and the `PDF_PROCESSOR_URL` read inside the latter — have
never been on a request path. The contract in §F2 of the integrations reference
describes the live chain, not the unwired one.

They arrived together and the two are materially different products: the live
chain leads with `extract-webpage`'s own fetch, the unwired one leads with the
Puppeteer render. Switching changes what *every* article extraction does, so it
wants a deliberate decision rather than being settled inside an unrelated
change. Until then `defaultTiersFor` carries a comment saying it is not wired.

Two more helpers from the same change are dead for the same reason:
`loadCiteExtractor` and `articleViaCiteExtractor` are defined and never called
— the live scraper tier reaches `extract-webpage` through
`articleFromRenderedHtml` instead. Lint reports both as unused.

**Decide:** adopt `defaultTiersFor` (and rewrite §F2 to match), or delete it,
the two tiers it names, and the two helpers above.

### 1.5 Extraction settings resolution ✅

The extraction chain no longer hard-codes its knobs.
`worker/qwksearch/extractSettings.ts` owns one `ExtractionSettings` value, and
folds it out of three layers — shipped defaults, then Worker env, then
per-request overrides — validating every value on the way in. `tiersForUrl`
binds the resolved settings into each tier, so a tier no longer reaches for
`process.env` itself.

| Setting | Env var | Reaches |
|---|---|---|
| Citation style (`apa`/`mla`/`chicago`) | `QWKSEARCH_CITATION_STYLE` | `buildCite`, every tier |
| Transcript languages | `QWKSEARCH_EXTRACT_LANGUAGES` | `extract-youtube` via `languages` |
| Extractor timeout | `QWKSEARCH_EXTRACT_TIMEOUT` | `extract-webpage` `timeout` |
| Enabled tiers, in order | `QWKSEARCH_EXTRACT_TIERS` | `tiersForUrl` |
| Render backend + budget | `SCRAPER_URL`, `SCRAPER_API_KEY`, `QWKSEARCH_SCRAPER_DEADLINE_MS` | the Puppeteer tier |
| PDF OCR mode + endpoint | `PDF_PROCESSOR`, `PDF_PROCESSOR_URL` | `extract-pdf` via `processor` |
| Outbound proxy | `QWKSEARCH_EXTRACT_PROXY` | `extract-webpage` `proxy` |
| Third-party reader fallback | `QWKSEARCH_EXTRACT_THIRD_PARTY_BACKUP` | `extract-webpage` |

Three things worth knowing before building the pane on top of it:

- **The client layer is deliberately narrower than the user layer.**
  `GET /api/doc/article` honours `?cite=` and `?lang=` and nothing else. Every
  other setting either names a host the Worker would then send a bearer token to
  (`scraperUrl`, `pdfProcessorUrl`, `proxy`) or buys the caller compute
  (`pdfProcessor=docling` OCRs every page). `ClientExtractionOverrides` is typed
  to exclude them and `parseClientExtractionOverrides` never reads them.
- **Citation style survives the cache.** `articleCache` is keyed by URL and holds
  one `cite` string, so a non-APA request re-renders the citation from the cached
  fields rather than fragmenting the cache per style. APA keeps the stored
  string, which came out of the extractor's 90k-name database and beats anything
  the fallback builder assembles from columns.
- **An empty tier list is a real outcome.** `QWKSEARCH_EXTRACT_TIERS=scraper`
  leaves a PDF URL with no viable tier, and the caller gets the "no extraction
  tier configured" error rather than a tier the operator switched off.

Follow-ups:

- ✅ **The user layer now has storage and an API.** See 1.6.
- ⬜ **MLA/Chicago only reach the fallback builder's fields.** The extractor's
  own citation is APA, so a non-APA style is rebuilt from `author_cite`, `title`,
  `source` and `date` — correct, but it loses the extractor's author-type
  handling (organizations, two-author, more-than-two). Teaching
  `extract-webpage` the other styles is the real fix.

### 1.6 Extraction preferences: the user layer ✅

1.5 defined a user layer and gave it nowhere to live —
`UserExtractionOverrides` was a type `resolveExtractionSettings` accepted and
nothing ever produced. It now has storage, an API and a caller:

- `worker/qwksearch/extractionPreferences.ts` — load / save / clear one user's
  overrides, and `userExtractionOverridesForRequest(headers)` for the article
  route. Every read is validated again on the way out and never throws; a
  failure resolves to `{}` and the caller falls back to the operator's config.
- `worker/routes/qwksearch/extractionSettings.ts` —
  `GET`/`PUT`/`DELETE /api/doc/extraction-settings`, sign-in required, returning
  `{ overrides, effective, options }`.
- `extraction_settings` on D1 (`migrations/d1/0002_extraction_settings.sql`,
  idempotent like 0001; both files run from `bun run cf:d1:migrate`).
- `/api/doc/article` folds the layer in between env and query, so precedence is
  now **default → env → user → `?cite=`/`?lang=`**. A request with no `cookie`
  header skips the session lookup, so the anonymous path is unchanged.

The full contract is §F2b of the integrations reference.

**Correction to the plan.** 2.2 below used to say the Extraction pane needed
"nothing further server-side". That was wrong: the resolver took a user layer,
but no code path produced one, so a pane writing to
`src/store/user/slices/settings/` would have changed nothing about an
extraction. That gap is what 1.6 closes.

**Deliberate deviation.** The plan said to persist through LobeHub's user
settings store. The overrides are on D1 instead, keyed by the same LobeHub user
id as favorites and documents. Reading Postgres `user_settings` from a Hono
Worker route would couple the extraction chain to Hyperdrive for a six-field
blob, and adding a namespace to it means an upstream type edit plus a Postgres
migration — the opposite of the "keep changes additive" rule below. Phase 2's
"one system of record" is about the settings *surface*, and there is still
exactly one: the pane. If the panes later consolidate onto the LobeHub store,
this route is the migration's read side.

Follow-ups:

- ✅ **The client consumer landed** — 1.7 below.
- ✅ **`languages` is capped at five and `tiers` at the four known ids**; the
  pane reads both bounds out of `options` and never repeats them.

### 1.7 Extraction settings pane ✅

2.2's Extraction half, shipped. `/settings/extraction` is a form over the one
JSON document 1.6 serves, and the first QwkSearch surface to live *inside*
LobeHub's settings shell rather than beside it. The full contract is §F2c of the
integrations reference.

```
src/features/Settings/extraction/
  index.tsx           SettingHeader + the form
  api.ts              GET/PUT/DELETE, and the response types
  formState.ts        form values ⇄ UserExtractionOverrides (pure, no React)
  features/ExtractionForm.tsx
```

Three things worth knowing before touching it:

- **An unset field is not a value.** `normalizeOverrides` drops `undefined`, so
  a field the user has not touched must be *absent* from the PUT body — not
  `null`, not `''`, and not the value that happens to be in force. Every input
  therefore has an explicit inherit state (`INHERIT` for the enums, an empty
  list, `null` for the timeout) and `overridesFromFormValues` omits those keys.
  This is why the third-party-fallback control is a three-way select rather than
  a `Switch`: `false` pins the user to off, unset follows the operator, and a
  switch cannot say both.
- **The inputs seed from `overrides`, never from `effective`.** Seeding from
  what is in force would turn every inherited field into an explicit override
  the moment the user saved anything, silently pinning them to today's server
  config. `effective` appears only as the hint under each input and as the
  timeout's placeholder.
- **The pane renders the response, not what it sent.** `PUT` trims — a sixth
  language, an unknown tier, a 99s timeout clamped to 60 — and the response is
  the authority.

`api.ts` restates the Worker's types instead of importing them, because `src/`
bundles for the browser and `worker/` for workerd. **`contract.test.ts` is the
drift guard**: it imports the real `extractSettings.ts`, rebuilds the exact
document the route returns, and runs a load → edit → save cycle back through
`normalizeOverrides`. An enum member or override field added on the server and
not in `api.ts` fails it.

Upstream edits are five registration points and no logic — the `SettingsTabs`
enum, both `componentMap`s, the sidebar item in `useCategory.tsx`, and the
compact-header title map in `SettingsContent.tsx`. No route file: `/settings/:tab`
already dispatches by enum value.

Follow-ups:

- ⬜ **`languages` is a free-text tag input.** Any BCP-47-shaped tag is accepted
  and the server drops what does not match, so a typo silently disappears rather
  than being flagged. A language picker is the fix.
- ⬜ **`tiers` is a plain multi-select**, so the execution order is the order the
  user happened to click. It is *stored* in that order and it matters — the
  control should be drag-to-reorder.
- ⬜ **A 401 shows the raw error text.** The pane needs sign-in and says
  "could not load your extraction settings"; it should recognise the 401 that
  `ExtractionSettingsApiError` already carries and prompt to sign in, the way
  `article.error.loginRequired` does.

## How to pick up the next item

**Suggested next, in order** — all code-only, all testable without Cloudflare
credentials:

1. **A `searchSettings.ts` for the Search & Sources pane**, mirroring
   `extractSettings.ts`: one resolved value, layered defaults → env → user, with
   the same rule that hosts and keys are environment-only. `QwkSearchImpl` reads
   `QWKSEARCH_SEARCH_URL` and its category normalizer straight from env today,
   the way the extraction tiers used to. Extraction took three passes to get
   here (1.5 → 1.6 → 1.7) and this is the first of the three; doing them in that
   order is what made each one testable on its own.
2. **1.3's open question — two chains in `extract.ts`.** `defaultTiersFor`,
   `extractViaYouTube`, `extractViaPdf`, `loadCiteExtractor` and
   `articleViaCiteExtractor` have never been on a request path, and lint reports
   two of them as unused. It is a decision, not a discovery: adopt or delete.
   Small, and it removes the only known dead code in the Worker.
3. **1.7's follow-ups**, all small and all user-visible: a language picker
   instead of free-text tags, a drag-to-reorder tier list, and a sign-in prompt
   on the 401 the pane currently shows as raw error text.
4. **5.4's bundle budget in CI.** The measurement exists (`bun run cf:budget`);
   what is missing is a workflow that runs it. That needs a job that installs and
   builds `packages-lobe`, which no workflow does yet — a CI-minutes decision as
   much as a code one, which is why it sits below the items above.
5. **2.1's settings map**, which the Search & Sources pane needs anyway and
   which is pure reading.

Then, for whichever you pick:

1. Prefer an item whose seam is already understood and whose "done" is testable
   without Cloudflare credentials — those are the ones a code-only run can finish.
2. Keep changes **additive**: new files under `worker/`, `src/features/QwkSearch/`
   or a new `impls/` directory. Edits to upstream files are the merge cost against
   LobeHub, so keep them to registration points (an enum, a switch, a route mount)
   and list every one in `packages-lobe/README.md` § What changed vs. upstream.
3. Ship a test with it. `bunx vitest run <path>` under `packages-lobe`.

   A full `pnpm install --ignore-scripts` inside `packages-lobe` **does** work in
   a code-only environment — it takes a few minutes and about 3 GB. Anything
   touching `src/` needs it, and it is what makes `bun run check <files>` (lint
   + auto-discovered related tests in one pass) available, which is the workflow
   `packages-lobe/AGENTS.md` documents. Prefer it unless the change is
   `worker/`-only.

   **Do not run `bun run check --type`.** The repo-wide type check reaches
   ~13.8 GB RSS and gets OOM-killed on a 15 GB box — twice observed now. Write a
   throwaway `tsconfig.scoped.json` that `extends` the real one and narrows
   `include` to the files you changed, then `npx tsgo --noEmit -p` it: about a
   minute, and it keeps the path aliases that passing bare filenames loses.
   Expect pre-existing errors from `apps/desktop` and `apps/server` in the
   output (missing `electron` types and similar) — filter to your own paths.
